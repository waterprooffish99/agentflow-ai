# Data Model: AgentFlow AI Platform Core

## Overview

SQLAlchemy 2.0 async models. All tables include `tenant_id` for row-level isolation. All tables include timestamps. Soft deletes preferred for audit trails.

---

## Entity Relationships

```
Tenant (1) ──────< User (many)
  │                    │
  ├──< Customer (many)
  │
  ├──< Lead (many) ────── (1) Customer
  │       │
  │       ├──< Conversation (many)
  │       │       │
  │       │       ├──< Message (stored as JSONB)
  │       │       └──< Correction (many)
  │       │
  │       └──< Appointment (many) ──── (1) Customer
  │
  ├──< Workflow (many)

```

## Models

### Tenant

```python
class Tenant(Base):
    __tablename__ = "tenants"

    id: UUID (PK)
    business_name: str (unique, indexed)
    domain: str (nullable)
    timezone: str (default "UTC")
    subscription_tier: Enum(free, starter, growth, enterprise)
    status: Enum(active, suspended, trial)
    autonomy_level: Enum(mode_1_supervised, mode_2_autonomous) (default "mode_1_supervised")
    min_reviewed_conversations: int  # Graduation threshold: defaults to 50
    max_correction_rate: float       # Graduation threshold: defaults to 0.10
    settings: JSONB  # flexible per-tenant config
    created_at: datetime
    updated_at: datetime
```

**Business Rules**:
- `subscription_tier` determines rate limits and feature flags
- `status` controls AI activation and API access
- `autonomy_level` determines whether responses can be delivered unsupervised
- `min_reviewed_conversations` and `max_correction_rate` specify the thresholds required for graduation to Mode 2 (autonomous)
- `settings` JSONB stores: business hours, services offered, staff list, AI personality config, FAQ answers

### User

```python
class User(Base):
    __tablename__ = "users"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)
    email: str (unique, indexed)
    password_hash: str
    role: Enum(super_admin, business_admin, staff)
    full_name: str
    status: Enum(active, inactive)
    email_verified: bool (default False)
    last_login: datetime (nullable)
    created_at: datetime
    updated_at: datetime
```

**Business Rules**:
- `role` determines API permissions; enforced via RBAC dependency in every route
- `tenant_id` is null for super_admin (platform-level user)
- Only one super_admin exists (seeded on platform init)
- Email is unique within a tenant (same email can exist in different tenants)

**Validation**:
- Email: valid format, max 255 chars
- Password: min 8 chars, stored as argon2 hash
- Role transitions: staff cannot become business_admin without admin action

```python
class Customer(Base):
    __tablename__ = "customers"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)
    name: str
    email: str (nullable, indexed)
    phone: str (nullable, indexed)
    location: str (nullable)  # city or zip code
    notes: Text (nullable)

    updated_at: datetime

    # Unique constraint: one customer per tenant per (name, email) or (name, phone)
```

**Business Rules**:
- Name is required; email or phone must exist for notification
- `tenant_id` + `email` is unique; `tenant_id` + `phone` is unique
- Customers are deduplicated by name + phone/email match

### Lead

```python
class Lead(Base):
    __tablename__ = "leads"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)
    customer_id: UUID (FK → Customer)
    conversation_id: UUID (FK → Conversation, nullable)

    status: Enum(unqualified, partially_qualified, qualified, booked, lost)
    source: str (nullable)  # "web_widget", "phone", "manual"
    urgency: Enum(low, medium, high, urgent)
    budget_range: str (nullable)  # e.g., "$50-100", "budget"
    preferred_service: str (nullable)
    preferred_times: JSONB  # ["morning", "weekends"]
    conversation_summary: Text (nullable)
    assigned_to: UUID (FK → User, nullable)
    qualifies_reason: Text (nullable)  # why qualified or disqualified
    created_at: datetime
    updated_at: datetime
```

**State Machine**:
```
unqualified → partially_qualified → qualified → booked
     ↓              ↓                ↓
    lost           lost             lost
```

**Business Rules**:
- Lead is `qualified` when: name + service + urgency + (email or phone) + preferred_times are all captured
- Lead is `booked` when: an Appointment record exists linked to this lead
- Lead status is updated automatically by AI tools and manually by staff
- Conversation summary is generated by AI after each conversation ends

**Validation**:
- `urgency` can only be set by AI during qualification or by staff
- `budget_range` is a string (not numeric) — captured as text from conversation

### Conversation

```python
class Conversation(Base):
    __tablename__ = "conversations"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)
    lead_id: UUID (FK → Lead, indexed)
    customer_id: UUID (FK → Customer)

    messages: JSONB  # [{"role": "user", "content": "...", "timestamp": "..."}, ...]
    status: Enum(active, escalated, closed)
    started_at: datetime
    ended_at: datetime (nullable)
    escalated_to: UUID (FK → User, nullable)
    escalated_reason: str (nullable)
    resolved_by: UUID (FK → User, nullable)
    resolved_at: datetime (nullable)
    created_at: datetime
    updated_at: datetime
```

**Business Rules**:
- `messages` is a JSONB array — enables efficient storage and retrieval
- `status` transitions: `active` → `escalated` (human takeover) → `closed`
- `status` can also be `active` → `closed` (normal customer departure)
- When escalating, the AI sends the conversation history to the assigned staff member

**Validation**:
- A lead can have multiple conversations over time
- Each conversation is independent (new conversation = new lead conversation thread)

### Correction

```python
class Correction(Base):
    __tablename__ = "corrections"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)
    conversation_id: UUID (FK → Conversation, indexed)
    ai_draft_message: str
    human_edited_message: str (nullable)  # Nullable if approved without edits
    was_edited: bool
    reviewed_by: UUID (FK → User, indexed)
    timestamp: datetime
    created_at: datetime
    updated_at: datetime
```

**Business Rules**:
- Every reply drafted by the AI under Mode 1 (Supervised) and reviewed by a human creates a Correction row.
- If approved as-is, `was_edited` is set to `False` and `human_edited_message` remains `null`.
- These records are the primary training and proof records for graduation evaluation.

### Appointment

```python
class Appointment(Base):
    __tablename__ = "appointments"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)
    customer_id: UUID (FK → Customer, indexed)
    lead_id: UUID (FK → Lead, nullable, indexed)

    service_type: str
    start_time: datetime (indexed)
    end_time: datetime
    status: Enum(confirmed, cancelled, rescheduled, completed, no_show)
    notes: Text (nullable)
    cancelled_by: UUID (FK → User, nullable)
    cancelled_reason: str (nullable)
    created_at: datetime
    updated_at: datetime

    # Constraint: end_time > start_time
    # Constraint: no overlapping appointments for the same customer
```

**State Machine**:
```
confirmed → completed (after the appointment time passes)
         → cancelled (customer or staff cancels)
         → rescheduled (moved to a different time)
         → no_show (appointment time passed, customer didn't arrive)
```

**Business Rules**:
- Booking creates an `Appointment` with `status: confirmed` and links to the `Lead`
- Rescheduling: create new appointment, mark old as `rescheduled`, link old to new
- Cancellation: mark as `cancelled`, send notification to customer and staff
- `service_type` must match one of the services defined in tenant settings
- Overlap detection: before confirming, check no existing confirmed/rescheduled appointment overlaps

**Validation**:
- `start_time` and `end_time` are stored in the business's timezone (from tenant settings)
- Future-only booking: `start_time` must be in the future
- Business hours: appointments must fall within the tenant's configured hours

### Workflow

```python
class Workflow(Base):
    __tablename__ = "workflows"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)

    name: str
    description: str (nullable)
    trigger_type: Enum(appointment_confirmed, lead_cold, no_show, manual, schedule)
    trigger_config: JSONB  # {"days_before": 1, "time": "09:00"} for schedule type
    actions: JSONB  # [{"type": "send_email", "template": "reminder", "delay": "24h"}]
    is_active: bool (default True)
    last_run_at: datetime (nullable)
    run_count: int (default 0)
    created_at: datetime
    updated_at: datetime
```

**Business Rules**:
- `trigger_type` determines when the workflow is evaluated
- `actions` is a list — workflows can chain multiple actions
- Workflows run asynchronously via a background task queue (Celery or similar)
- `last_run_at` and `run_count` enable monitoring and debugging

**Validation**:
- `trigger_config` schema varies by `trigger_type` — validated at the service layer
- `actions` list must have at least one action

### Notification

```python
class Notification(Base):
    __tablename__ = "notifications"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, indexed)

    recipient_type: Enum(customer, staff, admin)
    recipient_address: str  # email address or phone number
    channel: Enum(email, sms, whatsapp)
    template: str  # "booking_confirmation", "reminder", "escalation"
    context: JSONB  # {"customer_name": "...", "appointment_time": "...", ...}
    status: Enum(pending, sent, failed)
    sent_at: datetime (nullable)
    error_message: str (nullable)
    retry_count: int (default 0)
    created_at: datetime
    updated_at: datetime
```

**Business Rules**:
- `pending` → `sent` on success; `pending` → `failed` after 3 retries
- Failed notifications are logged; staff can manually retry
- Email via SMTP (dev) or SendGrid (prod); SMS via Twilio (future)
- `context` JSONB contains all template variables — enables templating without a separate engine

### AuditLog

```python
class AuditLog(Base):
    __tablename__ = "audit_logs"

    id: UUID (PK)
    tenant_id: UUID (FK → Tenant, nullable — null for platform-level actions)
    user_id: UUID (FK → User, nullable)

    action: str  # "lead.updated", "appointment.created", "user.login", "tenant.suspended", "ai.action_taken"
    entity_type: str  # "lead", "appointment", "user", "tenant", "conversation"
    entity_id: UUID (nullable)
    details: JSONB (nullable)  # e.g., {"tools_called": [...], "recommendation": "...", "outcome": "...", "approved_by": "..."}
    ip_address: str (nullable)
    user_agent: str (nullable)
    timestamp: datetime (indexed)
```

**Business Rules**:
- All state-changing operations create an AuditLog entry.
- For AI actions (Mode 2 actions or Mode 1 recommendations), the entry logs the type of AI action, tools called, recommendation draft, approving human (if any), and the final outcome (answering SC-010).
- Platform-level actions (tenant creation) have `tenant_id: null`
- Retention: 2 years minimum (configurable per tenant for compliance)

## Migrations Strategy

Alembic for all schema migrations. Migration approach:

1. All new columns must be nullable or have a default (no locking migrations)
2. Backward-compatible migrations only — old code must work during migration
3. No data migration in the same PR as schema migration
4. Feature flags gate new schema features

## Entity Constraints

| Rule | Enforcement |
|------|-------------|
| No cross-tenant data access | RLS policies on all tables + API dependency injection |
| Unique email per tenant | DB unique constraint on (tenant_id, email) for users |
| Unique policy per tenant | DB unique constraint on (tenant_id) for permission_policies |
| No double-booking | Service layer check + DB constraint on overlapping time ranges |
| Valid appointment times | Service layer validation (start < end, in future, within business hours) |
| Lead status transitions | Service layer state machine — no direct status overwrite |
| Workflow actions non-empty | Service layer validation |
